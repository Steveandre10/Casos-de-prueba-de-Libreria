Casos de Prueba - Libreria

1. Introducción

Este documento define el caso de prueba y el ambiente de pruebas para la funcionalidad de **gestión de devoluciones**. El sistema deberá permitir al encargado de inventario gestionar las solicitudes de devolución realizadas sobre productos adquiridos, permitiendo consultar y actualizar su estado.

2. Alcance de las pruebas (Qué se va a probar)

a. Código del Ticket #0901
b. Descripción de la historia El sistema deberá permitir al encargado de inventario gestionar devoluciones. Se verificará que pueda consultar las solicitudes de devolución y gestionar correctamente su estado de acuerdo con el proceso establecido.

3. Fuera de Alcance

  • Pruebas de rendimiento: No se evaluará la gestión simultánea de grandes cantidades de devoluciones.
  • Pruebas de seguridad: No se realizarán pruebas de penetración sobre el módulo de devoluciones.
  • Generación de notas crédito o débito: No se evaluará la generación automática de documentos, ya que corresponde al RF4.
  • Proceso de pago: No se evaluará la devolución del dinero al usuario.
  • Facturación electrónica externa: No se evaluará la comunicación con sistemas gubernamentales.

4. Tipos de prueba / Estrategia (Cómo ejecutar las pruebas)

  • Prueba funcional: Verificar que se puedan gestionar las solicitudes de devolución.
  • Prueba de validación: Comprobar que la información de la devolución corresponda al pedido y producto.
  • Prueba de estados: Verificar los diferentes estados posibles de una devolución.
  • Prueba de escenarios: Realizar pruebas con diferentes productos y cantidades.
  • Prueba exploratoria: Consultar y gestionar diferentes solicitudes para identificar errores.
  • Cross-browser testing (Múltiples browsers): Verificar el funcionamiento en Chrome, Firefox y Edge.
  • Cross mobile testing (Emulado con Chrome): Comprobar el funcionamiento mediante dispositivos móviles o emulación móvil.

5. Ambiente de prueba

La prueba se realizará en un ambiente aislado de producción, donde se implementará la versión más reciente del código. La URL para las pruebas será la siguiente:

Acceder al Ambiente de Pruebas

6. Datos de pruebas

Los datos utilizados para las pruebas serán los siguientes:

Usuario encargado Usuario con permisos para gestionar devoluciones.
Usuario solicitante Usuario que realizó la compra.
Pedido Pedido asociado a la devolución.
Número de pedido Identificador válido del pedido.
Producto Libro incluido en el pedido.
Cantidad Cantidad de unidades solicitadas para devolución.
Motivo de devolución Motivo registrado por el usuario.
Solicitud de devolución Solicitud registrada en el sistema.
Estado inicial Estado actual de la solicitud antes de ser gestionada.
Estado final Estado asignado después de gestionar la solicitud.

7. Riesgos

Riesgo Probabilidad Impacto Mitigación
La solicitud no aparece en el módulo de devoluciones Media Alto Verificar la creación y registro de diferentes solicitudes.
El sistema no permite gestionar la devolución Media Alto Validar permisos y probar diferentes solicitudes.
El estado no se actualiza correctamente Media Alto Verificar el estado antes y después de guardar los cambios.
La devolución se relaciona con un pedido incorrecto Baja Alto Validar el número de pedido y producto asociado.
Se permite gestionar una solicitud inexistente Baja Alto Realizar consultas con identificadores inválidos.
Los datos de la devolución son incorrectos Media Alto Comparar la solicitud con el pedido original.
