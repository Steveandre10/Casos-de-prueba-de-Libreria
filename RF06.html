Casos de Prueba - Libreria

1. Introducción

Este documento define el caso de prueba y el ambiente de pruebas para la funcionalidad de generación de reportes del historial de transacciones por usuario. El sistema deberá permitir al personal de facturación consultar y generar reportes relacionados con las transacciones realizadas por los usuarios.

2. Alcance de las pruebas (Qué se va a probar)

a. Código del Ticket #0601
b. Descripción de la historia El sistema deberá permitir al personal de facturación generar reportes del historial de transacciones por usuario. Se verificará que los reportes presenten correctamente la información de las transacciones realizadas y permitan identificar al usuario relacionado con cada operación.

3. Fuera de Alcance

  • Pruebas de rendimiento: No se evaluará la generación de reportes con millones de transacciones simultáneas.
  • Pruebas de seguridad: No se realizarán pruebas de penetración sobre el módulo de reportes.
  • Creación de usuarios: No se evaluará el registro o creación de nuevas cuentas de usuario.
  • Modificación de transacciones: No se evaluará la edición manual de transacciones históricas.
  • Integración gubernamental: No se evaluará la comunicación con sistemas de facturación electrónica externos, ya que corresponde al RF5.

4. Tipos de prueba / Estrategia (Cómo ejecutar las pruebas)

  • Prueba funcional: Verificar que el sistema permita generar reportes del historial de transacciones.
  • Prueba de validación: Comprobar que los datos mostrados correspondan a las transacciones reales del usuario.
  • Prueba de filtros: Verificar la consulta utilizando diferentes usuarios y criterios de búsqueda.
  • Prueba de escenarios: Realizar reportes con usuarios que tengan diferentes cantidades de transacciones.
  • Prueba exploratoria: Utilizar diferentes combinaciones de filtros para identificar errores en la generación del reporte.
  • Cross-browser testing (Múltiples browsers): Verificar el funcionamiento en Chrome, Firefox y Edge.
  • Cross mobile testing (Emulado con Chrome): Comprobar el acceso al módulo de reportes mediante dispositivos móviles o emulación móvil.

5. Ambiente de prueba

La prueba se realizará en un ambiente aislado de producción, donde se implementará la versión más reciente del código. La URL para las pruebas será la siguiente:

Acceder al Ambiente de Pruebas

6. Datos de pruebas

Los datos utilizados para las pruebas serán los siguientes:

Usuario encargado Usuario con permisos para consultar y generar reportes.
Usuario consultado Usuario registrado con transacciones realizadas.
Identificador del usuario Identificador válido del usuario seleccionado.
Transacciones Conjunto de compras realizadas por el usuario.
Número de transacción Identificador válido de cada transacción.
Fecha de transacción Fecha correspondiente a cada operación realizada.
Valor de transacción Valor registrado para cada compra.
Factura Factura asociada a cada transacción.
Filtros Criterios utilizados para consultar el historial de transacciones.
Reporte generado Reporte correspondiente al historial del usuario seleccionado.

7. Riesgos

Riesgo Probabilidad Impacto Mitigación
El reporte no se genera correctamente Media Alto Realizar pruebas con diferentes usuarios y cantidades de transacciones.
El reporte muestra transacciones de otro usuario Baja Alto Comparar las transacciones mostradas con el usuario seleccionado.
Faltan transacciones en el reporte Media Alto Comparar el reporte con las transacciones registradas en el sistema.
Los datos del reporte son incorrectos Media Alto Validar fechas, valores, identificadores y facturas asociadas.
Los filtros no funcionan correctamente Media Medio Realizar consultas utilizando diferentes combinaciones de filtros.
El reporte no refleja información actualizada Baja Alto Crear una transacción de prueba y verificar posteriormente su aparición en el historial.
