Casos de Prueba - Libreria

1. Introducción

Este documento define el caso de prueba y el ambiente de pruebas para la funcionalidad de **generación de reportes sobre movimientos de inventario**. El sistema deberá permitir al encargado de inventario consultar y generar reportes relacionados con las entradas, salidas y demás movimientos que afecten las existencias de los libros.

2. Alcance de las pruebas (Qué se va a probar)

a. Código del Ticket #0801
b. Descripción de la historia El sistema deberá permitir al encargado de inventario generar reportes sobre movimientos con respecto a existencias. Se verificará que los reportes presenten correctamente los movimientos de inventario realizados y su impacto sobre las existencias registradas.

3. Fuera de Alcance

  • Pruebas de rendimiento: No se evaluará la generación de reportes con cantidades masivas de movimientos.
  • Pruebas de seguridad: No se realizarán pruebas de penetración sobre el módulo de inventario.
  • Modificación de movimientos: No se evaluará la modificación manual de movimientos históricos.
  • Registro de nuevos libros: No se evaluará la creación de libros, ya que corresponde al RF13.
  • Consulta en tiempo real: No se evaluará específicamente la actualización en tiempo real del inventario, ya que corresponde al RF14.

4. Tipos de prueba / Estrategia (Cómo ejecutar las pruebas)

  • Prueba funcional: Verificar que el sistema permita generar reportes de movimientos.
  • Prueba de validación: Comprobar que los datos del reporte coincidan con los movimientos registrados.
  • Prueba de filtros: Realizar consultas utilizando diferentes períodos y criterios.
  • Prueba de escenarios: Generar reportes con entradas, salidas y diferentes productos.
  • Prueba exploratoria: Utilizar diferentes combinaciones de criterios para identificar posibles errores.
  • Cross-browser testing (Múltiples browsers): Verificar el funcionamiento en Chrome, Firefox y Edge.
  • Cross mobile testing (Emulado con Chrome): Comprobar el acceso y funcionamiento mediante dispositivos móviles o emulación móvil.

6. Datos de pruebas

Los datos utilizados para las pruebas serán los siguientes:

Usuario Usuario registrado con permisos para gestionar inventario.
Libro Libro registrado en el inventario.
Código del libro Identificador válido del libro.
Movimiento de entrada Entrada de unidades al inventario.
Movimiento de salida Salida de unidades del inventario.
Cantidad Número de unidades involucradas en el movimiento.
Fecha del movimiento Fecha en la que se realizó la operación.
Tipo de movimiento Entrada, salida o ajuste de inventario.
Reporte generado Reporte correspondiente a los movimientos consultados.

7. Riesgos

Riesgo Probabilidad Impacto Mitigación
El reporte no se genera correctamente Media Alto Realizar pruebas con diferentes tipos de movimientos.
El reporte muestra información incorrecta Media Alto Comparar los datos del reporte con los registros del inventario.
Faltan movimientos en el reporte Media Alto Verificar el historial completo de movimientos.
Se muestran movimientos de productos incorrectos Baja Alto Validar el código y nombre del libro en cada registro.
Los filtros generan resultados incorrectos Media Medio Realizar búsquedas con diferentes períodos y criterios.
El reporte no refleja movimientos recientes Baja Alto Registrar un movimiento y verificar posteriormente su aparición en el reporte.
