Casos de Prueba - Libreria

1. Introducción

Este documento define el caso de prueba y el ambiente de pruebas para la funcionalidad de **consulta del inventario en tiempo real**. El sistema deberá permitir al encargado de inventario consultar las existencias actuales de los libros y visualizar los cambios realizados sobre el stock de manera actualizada.

2. Alcance de las pruebas (Qué se va a probar)

a. Código del Ticket #1401
b. Descripción de la historia El sistema deberá permitir al encargado de inventario consultar el inventario en tiempo real. Se verificará que las existencias mostradas correspondan con el stock actual registrado y que los cambios realizados sean reflejados correctamente.

3. Fuera de Alcance

  • Pruebas de rendimiento: No se evaluará el comportamiento con una cantidad masiva de consultas simultáneas.
  • Pruebas de seguridad: No se realizarán pruebas de penetración.
  • Registro de nuevos libros: No se evaluará la creación de nuevos productos, ya que corresponde al RF13.
  • Configuración de alertas: No se evaluará la configuración de niveles mínimos, correspondiente al RF11.
  • Generación de reportes: No se evaluará la generación de reportes de movimientos, correspondiente al RF8.

4. Tipos de prueba / Estrategia (Cómo ejecutar las pruebas)

  • Prueba funcional: Verificar que el inventario pueda consultarse correctamente.
  • Prueba de actualización: Comprobar que los cambios de stock se reflejen correctamente.
  • Prueba de validación: Comparar las existencias mostradas con los registros de inventario.
  • Prueba de escenarios: Realizar entradas y salidas de diferentes libros.
  • Prueba de consistencia: Verificar que el stock mostrado después de cada movimiento sea correcto.
  • Prueba exploratoria: Realizar diferentes movimientos y consultas consecutivas.
  • Cross-browser testing (Múltiples browsers): Verificar el funcionamiento en Chrome, Firefox y Edge.
  • Cross mobile testing (Emulado con Chrome): Comprobar la consulta mediante dispositivos móviles o emulación móvil.

6. Datos de pruebas

Los datos utilizados para las pruebas serán los siguientes:

Usuario Usuario registrado con permisos para consultar inventario.
Libro Libro registrado en el inventario.
Código del libro Identificador válido del libro.
Stock inicial Cantidad de unidades disponible antes del movimiento.
Movimiento de entrada Cantidad de unidades agregadas al inventario.
Movimiento de salida Cantidad de unidades retiradas del inventario.
Stock esperado Cantidad que debería mostrar el sistema después del movimiento.
Stock mostrado Cantidad visualizada en el inventario después de la actualización.
Fecha y hora de consulta Momento en que se verifica la información actualizada.

7. Riesgos

Riesgo Probabilidad Impacto Mitigación
El inventario no se actualiza después de un movimiento Media Alto Realizar diferentes entradas y salidas y consultar nuevamente el inventario.
El stock mostrado es incorrecto Media Alto Comparar el valor mostrado con el stock esperado.
Existe retraso en la actualización Media Alto Realizar movimientos y verificar inmediatamente la información mostrada.
El sistema muestra información desactualizada Media Alto Actualizar o volver a consultar el inventario después de cada movimiento.
Las cantidades de diferentes libros se mezclan Baja Alto Realizar movimientos sobre varios libros y verificar cada registro individualmente.
El inventario no coincide con los movimientos registrados Media Alto Comparar el historial de movimientos con las existencias actuales.
