Casos de Prueba - Libreria

1. Introducción

Este documento define el caso de prueba y el ambiente de pruebas para la funcionalidad de reenvío e impresión de factura. El sistema deberá permitir al usuario reenviar una factura previamente generada a un correo electrónico alternativo y disponer de una opción para imprimirla.

2. Alcance de las pruebas (Qué se va a probar)

a. Código del Ticket #0201
b. Descripción de la historia El sistema deberá permitir al usuario reenviar la factura electrónica generada después de una compra a un correo electrónico alternativo o imprimirla. Se verificará que ambas opciones funcionen correctamente y que la factura corresponda al pedido seleccionado.

3. Fuera de Alcance

  • Pruebas de rendimiento: No se evaluará el envío masivo de facturas a múltiples correos simultáneamente.
  • Pruebas de seguridad: No se realizarán pruebas de penetración sobre el sistema de correo.
  • Modificacion de facturas: No se probará la modificación del contenido de la factura antes de enviarla o imprimirla.
  • Procesamiento de pagos: La generación de la factura no será evaluada en profundidad, ya que esta funcionalidad corresponde al RF1.

4. Tipos de prueba / Estrategia (Cómo ejecutar las pruebas)

  • Pruebas ágiles / funcionales basadas en historias de usuario + exploración:Verificar que las opciones de reenviar e imprimir factura estén disponibles y funcionen correctamente.
  • Prueba de validación: Comprobar que el sistema valide correctamente la dirección de correo ingresada.
  • Prueba de envío: Verificar que la factura sea enviada al correo electrónico alternativo proporcionado.
  • Prueba de impresión:Realizar diferentes compras y consultar sus respectivas facturas para identificar posibles errores.
  • Cross-browser testing (Múltiples browsers): Verificar la visualización y descarga de la factura utilizando diferentes navegadores como Chrome, Edge y Firefox.
  • Cross mobile testing (Emulado con Chrome): Comprobar que el usuario pueda acceder y descargar la factura desde un dispositivo móvil mediante la emulación de Chrome.

5. Ambiente de prueba

La prueba se realizará en un ambiente aislado de producción, donde se implementará la versión más reciente del código. La URL para las pruebas será la siguiente:

Acceder al Ambiente de Pruebas

6. Datos de pruebas

Los datos utilizados para las pruebas serán los siguientes:

Usuarios Usuario registrado y con sesión iniciada.
Correo electronico Correo válido asociado a la cuenta de usuario.
Producto Libro disponible en el catálogo.
Cantidad Una o más unidades del producto.
Pedido Pedido confirmado y asociado al usuario
Número de pedido Identificador válido generado por el sistema
Factura Factura electrónica generada después de confirmar la compra.
Valor de compra Archivo generado por el sistema para su visualizacion y descarga.

7. Riesgos

Riesgo Probabilidad Impacto Mitigación
La factura no se envía al correo alternativo Media Alto Realizar pruebas utilizando diferentes correos electrónicos válidos y verificar el envío.
El sistema permite ingresar un correo electrónico inválido Media Medio Validar el formato del correo antes de realizar el envío.
La factura enviada no corresponde al pedido seleccionado Bajo Alto Comparar el número de pedido, productos y valores de la factura antes y después del envío.
La vista de impresión presenta información incompleta Media Medio Revisar el contenido de la factura
La opción de impresión no funciona correctamente Media Medio Realizar pruebas en diferentes navegadores y verificar la vista previa de impresión.
El formato de la factura se altera al imprimir Baja Medio Comprobar la distribución y legibilidad de la factura en la vista de impresión.
