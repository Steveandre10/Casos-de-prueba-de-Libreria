Casos de Prueba - Libreria

1. Introducción

Este documento define el caso de prueba y el ambiente de pruebas para la funcionalidad de selección de métodos de pago. El sistema deberá permitir al usuario seleccionar uno de los métodos de pago disponibles al momento de realizar una compra y continuar correctamente con el proceso de pago.

2. Alcance de las pruebas (Qué se va a probar)

a. Código del Ticket #0301
b. Descripción de la historia El sistema deberá permitir al usuario seleccionar entre los diferentes métodos de pago disponibles para completar una compra. Se verificará que los métodos de pago se muestren correctamente y que el usuario pueda seleccionar uno para continuar con la transacción.

3. Fuera de Alcance

  • Pruebas de rendimiento: No se evaluará el comportamiento del sistema con una gran cantidad de transacciones simultáneas.
  • Pruebas de seguridad: No se realizarán pruebas de penetración ni análisis especializado de seguridad sobre las plataformas de pago.
  • Validación bancaria: No se comprobará el funcionamiento interno de bancos, entidades financieras o proveedores externos de pago.
  • Reembolsos: No se evaluará el proceso de devolución del dinero después de realizar un pago.
  • Generación de facturas: La generación y descarga de la factura no será evaluada en profundidad, ya que corresponde a otros requisitos funcionales.

4. Tipos de prueba / Estrategia (Cómo ejecutar las pruebas)

  • Prueba funcional: Verificar que los métodos de pago disponibles se muestren correctamente.
  • Prueba de selección: Comprobar que el usuario pueda seleccionar un método de pago.
  • Prueba de validación: Verificar que el sistema solicite la información necesaria según el método seleccionado.
  • Prueba de navegación: Comprobar que el usuario pueda continuar con el proceso después de seleccionar el método de pago.
  • Prueba exploratoria: Probar diferentes métodos disponibles para identificar comportamientos inesperados.
  • Cross-browser testing (Múltiples browsers): Verificar el funcionamiento en Chrome, Firefox y Edge.
  • Cross mobile testing (Emulado con Chrome): Comprobar la selección de métodos de pago en dispositivos móviles mediante la emulación de Chrome.

5. Ambiente de prueba

La prueba se realizará en un ambiente aislado de producción, donde se implementará la versión más reciente del código. La URL para las pruebas será la siguiente:

Acceder al Ambiente de Pruebas

6. Datos de pruebas

Los datos utilizados para las pruebas serán los siguientes:

Usuario Usuario registrado con acceso al sistema.
Correo electrónico Correo electrónico válido asociado al usuario.
Producto Libro disponible en el catálogo.
Cantidad Una o más unidades del producto seleccionado.
Carrito Carrito con productos disponibles para compra.
Valor de compra Valor total correspondiente a los productos seleccionados.
Métodos de pago Métodos de pago configurados y disponibles en el sistema.
Datos de pago Información de prueba requerida por el método de pago seleccionado.
Estado de la compra Compra pendiente de completar el pago.

7. Riesgos

Riesgo Probabilidad Impacto Mitigación
Los métodos de pago no aparecen disponibles Media Alto Verificar la configuración de los métodos de pago antes de ejecutar las pruebas.
El usuario no puede seleccionar un método de pago Media Alto Probar la selección de cada método disponible y verificar la interacción de los controles.
El sistema no valida los datos requeridos Media Alto Utilizar datos válidos e inválidos para comprobar las validaciones correspondientes.
El método seleccionado no se conserva al continuar Baja Medio Verificar que el método seleccionado permanezca registrado durante el proceso de compra.
El proceso de pago presenta errores después de seleccionar el método Media Alto Realizar pruebas con los diferentes métodos disponibles y revisar los mensajes generados por el sistema.
La selección de métodos presenta problemas en dispositivos móviles Baja Medio Realizar pruebas en diferentes tamaños de pantalla y navegadores móviles emulados.
