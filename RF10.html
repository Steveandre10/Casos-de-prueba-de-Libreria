Casos de Prueba - Libreria

1. Introducción

Este documento define el caso de prueba y el ambiente de pruebas para la funcionalidad de **notificaciones de inventario bajo**. El sistema deberá notificar al encargado de inventario cuando algún libro se encuentre próximo a agotarse, permitiendo tomar acciones oportunas para evitar la falta de existencias.

2. Alcance de las pruebas (Qué se va a probar)

a. Código del Ticket #1001
b. Descripción de la historia El sistema deberá permitir al encargado de inventario recibir notificaciones cuando algún libro esté próximo a agotarse. Se verificará que la notificación se genere cuando las existencias alcancen el nivel establecido para generar la alerta.

3. Fuera de Alcance

  • Pruebas de rendimiento: No se evaluará el envío masivo de notificaciones.
  • Pruebas de seguridad: No se realizarán pruebas de penetración sobre el sistema de notificaciones.
  • Configuración personalizada de alertas: No se evaluará la configuración individual de niveles mínimos, ya que corresponde al RF11.
  • Proceso de compra: No se evaluará el funcionamiento completo de las compras realizadas por los usuarios.
  • Reposición de inventario: No se evaluará el proceso de abastecimiento de productos.

4. Tipos de prueba / Estrategia (Cómo ejecutar las pruebas)

  • Prueba funcional: Verificar que se genere una notificación cuando el inventario alcance el nivel establecido.
  • Prueba de validación: Comprobar que la notificación corresponda al libro correcto.
  • Prueba de escenarios: Probar diferentes cantidades de existencias.
  • Prueba de límites: Verificar el comportamiento cuando las existencias estén por encima, en el límite y por debajo del nivel de alerta.
  • Prueba exploratoria: Realizar diferentes movimientos de inventario para comprobar el comportamiento de las alertas.
  • Cross-browser testing (Múltiples browsers): Verificar el funcionamiento en Chrome, Firefox y Edge.
  • Cross mobile testing (Emulado con Chrome): Comprobar la recepción y visualización de las notificaciones en dispositivos móviles o emulación.

5. Ambiente de prueba

6. Datos de pruebas

Los datos utilizados para las pruebas serán los siguientes:

Usuario Usuario con permisos para gestionar inventario.
Libro Libro registrado en el inventario.
Stock inicial Cantidad inicial disponible del libro.
Nivel de alerta Cantidad de existencias a partir de la cual se genera la alerta.
Movimiento Operación que reduzca las existencias.
Stock resultante Cantidad disponible después del movimiento.
Notificación Alerta generada por el sistema.
Estado de la alerta Estado de la notificación generada.

7. Riesgos

Riesgo Probabilidad Impacto Mitigación
No se genera la notificación Media Alto Realizar pruebas con diferentes niveles de existencias.
La notificación se genera antes de alcanzar el límite Media Medio Probar cantidades superiores al nivel establecido.
La notificación no identifica el libro correcto Baja Alto Comparar la información de la alerta con el inventario.
La notificación se genera varias veces innecesariamente Media Medio Realizar movimientos consecutivos y revisar el comportamiento.
La alerta no se muestra al encargado Media Alto Verificar permisos y mecanismos de notificación.
La información de la alerta es incorrecta Baja Alto Comparar el stock mostrado con el inventario real.
