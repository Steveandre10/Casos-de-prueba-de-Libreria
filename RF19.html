Casos de Prueba - Libreria (Roles y Permisos)

1. Introducción

Este documento define los casos de prueba y el ambiente de pruebas para la funcionalidad de gestión de roles y permisos personalizados. El sistema deberá permitir al administrador crear, asignar y modificar roles internos, garantizando que cada usuario tenga acceso únicamente a las funciones autorizadas según su perfil.

2. Alcance de las pruebas

a. Código del Ticket #0304
b. Descripción de la historia El sistema deberá permitir al administrador definir roles y permisos personalizados para distintos tipos de usuarios internos (ejemplo: administrador, gestor de inventario, soporte, auditor). Se verificará que los permisos asignados se reflejen correctamente en las funcionalidades disponibles para cada rol.

3. Fuera de Alcance

  • Pruebas de rendimiento: No se evaluará el comportamiento del sistema con miles de usuarios simultáneos.
  • Pruebas de seguridad avanzada: No se realizarán pruebas de penetración ni auditorías externas.
  • Integración con sistemas externos: No se probará la sincronización de roles con aplicaciones de terceros.
  • Gestión de usuarios externos: Este requerimiento se centra únicamente en usuarios internos.

4. Tipos de prueba / Estrategia

  • Prueba funcional: Verificar que el administrador pueda crear, editar y eliminar roles.
  • Prueba de validación: Comprobar que los permisos asignados se reflejen en las funcionalidades disponibles.
  • Prueba de restricción: Intentar acceder a funciones no autorizadas con un rol limitado.
  • Prueba exploratoria: Crear diferentes combinaciones de roles y permisos para identificar inconsistencias.
  • Cross-browser testing: Validar la gestión de roles en Chrome, Edge y Firefox.
  • Cross mobile testing: Comprobar que la administración de roles sea accesible desde dispositivos móviles.

5. Ambiente de prueba

La prueba se realizará en un ambiente aislado de producción, con la versión más reciente del código.

6. Datos de pruebas

Usuarios internos Administrador, Gestor de inventario, Auditor, Soporte
Credenciales Correo válido y contraseña asociada
Roles Definidos por el administrador en el sistema
Permisos Acceso a módulos específicos (ejemplo: catálogo, facturación, reportes)
Acciones restringidas Funciones bloqueadas según el rol asignado

7. Riesgos

Riesgo Probabilidad Impacto Mitigación
El administrador no puede crear un nuevo rol Media Alto Validar la creación de roles en diferentes escenarios.
Los permisos asignados no se reflejan correctamente Alta Alto Probar cada rol con casos de uso específicos.
Un usuario accede a funciones no autorizadas Media Alto Realizar pruebas de restricción y validación de accesos.
Error al modificar roles existentes Baja Medio Verificar la edición y actualización de roles en pruebas repetidas.
La interfaz no muestra correctamente los permisos Media Medio Probar en diferentes navegadores y dispositivos.
