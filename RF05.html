Casos de Prueba - Libreria

1. Introducción

Este documento define el caso de prueba y el ambiente de pruebas para la funcionalidad de integración con sistemas de facturación electrónica gubernamentales. El sistema deberá validar en tiempo real las facturas electrónicas generadas, verificando que la información enviada sea procesada correctamente por el sistema externo correspondiente.

2. Alcance de las pruebas (Qué se va a probar)

a. Código del Ticket #0501
b. Descripción de la historia El sistema deberá permitir la integración con sistemas de facturación electrónica gubernamentales para validación en tiempo real. Se verificará que las facturas generadas por el sistema sean enviadas correctamente al sistema externo y que la respuesta de validación sea recibida y registrada.

3. Fuera de Alcance

  • Pruebas de rendimiento: No se evaluará el comportamiento ante el envío masivo de facturas electrónicas.
  • Pruebas de seguridad: No se realizarán pruebas de penetración sobre la integración con el sistema gubernamental.
  • Configuración del sistema gubernamental: No se evaluará la configuración interna de la plataforma externa.
  • Proceso de pago: No se evaluará el funcionamiento de los métodos de pago utilizados para realizar la compra.
  • Gestión de devoluciones: No se evaluará la generación de notas crédito o débito, ya que corresponde al RF4.

4. Tipos de prueba / Estrategia (Cómo ejecutar las pruebas)

  • Prueba funcional: Verificar que una factura electrónica sea enviada correctamente para validación.
  • Prueba de integración: Comprobar la comunicación entre el sistema de la librería y el sistema gubernamental.
  • Prueba de validación: Verificar que la respuesta recibida sea registrada correctamente.
  • Prueba de escenarios: Realizar facturas con diferentes productos, cantidades y valores.
  • Prueba de manejo de errores: Comprobar el comportamiento cuando el servicio externo no responde o rechaza la factura.
  • Cross-browser testing (Múltiples browsers): Verificar el funcionamiento en Chrome, Firefox y Edge.
  • Cross mobile testing (Emulado con Chrome): Comprobar el acceso y funcionamiento mediante dispositivos móviles o emulación móvil.

6. Datos de pruebas

Los datos utilizados para las pruebas serán los siguientes:

Usuario Usuario registrado y autorizado para realizar compras.
Pedido Pedido confirmado y listo para facturación.
Número de pedido Identificador válido del pedido.
Producto Libro disponible en el catálogo.
Cantidad Cantidad de libros incluidos en la compra.
Valor de compra Valor correspondiente a los productos adquiridos.
Datos de facturación Información válida del comprador necesaria para generar la factura.
Factura electrónica Factura generada por el sistema después de confirmar la compra.
Respuesta del sistema externo Respuesta de validación de la factura electrónica.
Estado de validación Aprobada, rechazada o pendiente según la respuesta recibida.

7. Riesgos

Riesgo Probabilidad Impacto Mitigación
La factura no se envía al sistema gubernamental Media Alto Verificar la comunicación y realizar diferentes escenarios de generación de facturas.
El sistema no recibe la respuesta de validación Media Alto Comprobar la comunicación y el registro de respuestas del servicio externo.
La factura es rechazada por información incorrecta Media Alto Validar los datos de facturación antes de realizar el envío.
El estado de la factura no se actualiza correctamente Media Alto Comparar la respuesta del sistema externo con el estado mostrado en el sistema.
El servicio gubernamental no se encuentra disponible Media Alto Realizar pruebas con escenarios de indisponibilidad y verificar el manejo del error.
La información enviada no coincide con la factura generada Baja Alto Comparar los datos enviados con los datos registrados en la factura original.
